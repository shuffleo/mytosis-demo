# Voronoi Microscope Journal

## Product requirements and implementation ledger

**Document version:** 1.0  
**Requirements through:** 2026-11-10  
**Prototype:** `2026-offsite-ai-design-excercise`

## 1. Product definition

The product is a local-first reflective journal rendered as a living, circular microscope specimen. Journal thoughts occupy weighted Voronoi cells that can be added, edited, resized, moved, grouped, merged, split, clustered, and edited through an alternate bullet-list surface. The experience should feel organic and microscopic without sacrificing deterministic geometry, readable text, native editing, accessibility, or reversibility.

### Product principles

1. Geometry is real. Cell size, group walls, gaps, and neighboring movement come from the power diagram, not disconnected visual transforms.
2. Text remains editable and authoritative. Visual truncation may occur only under extreme spatial constraints; stored text is never truncated.
3. Motion communicates state, then settles. Text should not pulse or jitter with living-cell geometry.
4. Automation remains browser-local, cancellable, attributable, and undoable.
5. Alternate views operate on one shared versioned document.
6. Microscope effects process the specimen, not the toolbar, panel, or focused native editor.

## 2. Experience surfaces

### 2.1 Microscope

- Full-viewport Paper.js canvas.
- Circular specimen field with black exterior.
- Weighted, circle-clipped Voronoi cells.
- Bottom-centered tool dock and collapsible right-side settings panel.
- WebGL microscope treatment over the complete specimen.

### 2.2 Focused text editing

- Entered by double-clicking a journal cell.
- Camera zooms the selected cell to approximately 80% of the microscope diameter and centers it.
- A short blur spike masks the camera move, then returns to sharpness.
- Native transparent textarea is integrated into the cell.

### 2.3 Bullet-list editor

- Alternate full-screen text-first view of the same document.
- Preserves group hierarchy, cell ordering, text, and group palette.
- Returns to the microscope through an animated optical transition.

## 14. Verification gates

Before accepting a change:

1. `npm run typecheck`
2. `npm run lint`
3. `npm test`
4. `npm run build`
5. `npm run test:e2e`
6. Desktop and mobile smoke checks with no console/page errors.
7. Confirm wall/nutrient source reports `wallCompositeMode: pre-shader` under WebGL.
8. Confirm the three named tight-gap fixtures produce a visible preview and a committed cell with a non-sliver minimum dimension.

## 15. Requirement precedence

- Later explicit requirements supersede earlier locations or behavior. Specifically, Undo/Redo moved from the sidebar to the toolbar.
- “SVG pencil effect” describes the visual algorithm and controls. The current live implementation uses equivalent turbulence/displacement in the pre-shader WebGL composition to satisfy the later requirement that the effect not be a misaligned above-shader layer. The actual SVG filter is retained for fallback.
- Visual ellipsis is allowed only under extreme crowding. Editing surfaces and serialized data always contain complete text.

## 16. Audit status

Six independent implementation audits were assigned, each covering exactly two user requirement messages. Confirmed skipped or partial requirements are reported separately so no unrequested historical changes are made without approval.

### Behavior-level candidates requiring confirmation

1. **Persistent grouped-cell tint** — the light member fill is currently applied only while its group is selected. The historical requirement reads as an always-on tint.
2. **Sticky resize-handle shape** — organic sticky geometry is implemented for merge/attach bridges, while resize handles remain simple circles. One historical phrase may have intended the handles themselves to be inward sticky blobs matching the wall stroke.
3. **Microscope editor keyboard parity** — the bullet-list editor supports Enter split, Option/Alt word movement, and cross-row arrows. The focused microscope editor commits on Enter. Historical wording is ambiguous about whether list behavior should also apply inside the focused cell editor.
4. **In-repository clustering plan** — the requested data-model and browser-local clustering plan exists in the project artifact store, but is not committed inside this repository.
